# Test Traceability (Plan §10)

This file maps every normative test requirement in [`herdr-bartender-plan.md`](../herdr-bartender-plan.md) §10 to the tests that enforce it. [`plan-resolutions.md`](plan-resolutions.md) amends the plan, and R18 there fixes the count at **68** numbered §10.1 invariants. The heading in §10.1 still says "60"; R18 overrides it.

Test ids are `module.Class.method`, so each one can be run directly:

```bash
python3 -m unittest tests.test_events.StatusEventTests.test_p05_unknown_status_debounced
```

## How the mapping is built and checked

Each §10.1 test carries a docstring that starts (or contains) `Plan §10.1 #N`. Combined tags such as `#33/#23` count for both numbers. The table below was extracted from those docstrings with `ast` (method docstrings, plus class docstrings that apply to every method in the class). Every id was then checked against `unittest` discovery, so no listed test is missing from the run.

To re-check coverage (prints `68` when every invariant has at least one tagged test):

```bash
grep -rhoE "§10\.1 #[0-9]+(/#[0-9]+)*" tests | grep -oE "#[0-9]+" | tr -d '#' | sort -un | wc -l
```

Status at the W5 gate:
- All 68 invariants have at least one tagged test: 158 links over 155 distinct tests.
- The suite has 742 tests, none skipped and no expected failures.
- **Gaps closed at the gate:**
  - #8 previously had tests only by name (`test_p08_*`) and module docstring, so it failed the docstring grep. Its four tests are now tagged.
  - Six `test_pNN_*` tests whose docstrings lacked their number are now tagged too: #10 (2 tests), #18, #21, #54 and #60.
  - Only docstrings changed. No assertion changed.
- **Mutation-verified (W5)** means the W5 implementers applied the audit's surviving mutants (and new ones) to scratch copies, and each mutant made at least one listed test fail.
